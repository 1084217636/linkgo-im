# 02 服务器与网络最小基础

## 本章前置

你只需要理解客户端和服务端的区别。

## 本章目标

能解释 IP、端口、进程、请求、连接和协议；能看懂 `127.0.0.1:8090`。

## 进程是什么

编译后的 Go 程序运行起来，就是一个进程。进程拥有自己的内存。两个进程中的普通 Go map 互相看不见。

这个事实很重要：如果用户 A 的连接保存在 Gateway-1 的 map 中，Gateway-2 不能直接读取这个 map。

本章只记住这个问题，不急着解决。

## IP 和端口

IP 用于找到一台机器，端口用于找到这台机器上的某个网络程序。

```text
127.0.0.1:8090
```

- `127.0.0.1` 表示当前电脑。
- `8090` 表示 Gateway 监听的端口。

一台机器可以同时运行多个服务，只要监听不同端口。

## 请求和响应

客户端主动发一份数据给服务端，叫请求；服务端处理后返回数据，叫响应。

```text
客户端请求：我要登录，账号 userA，密码 123456
服务端响应：登录成功，这是你的令牌
```

## 连接是什么

网络连接可以先理解为客户端和服务端之间建立的一条通信通道。

短交互通常是：发送一个请求，收到一个响应，本次工作结束。聊天需要服务端随时把新消息推给客户端，所以还需要保持较长时间的连接。

## 协议是什么

协议是一套双方都遵守的数据规则。例如双方约定：登录使用某个地址、消息包含发送者和接收者、数字按某种格式编码。

协议不是某个具体程序，而是通信约定。

后面会遇到三种协议/调用形式：

- HTTP：浏览器发起登录、查历史等请求。
- WebSocket：浏览器和 Gateway 保持双向长连接。
- gRPC：LinkGo 内部 Go 服务之间调用。

本章只区分用途，不学习内部格式。

## 服务为什么可以运行多份

如果一份 Gateway 只能承受一定连接数，可以启动 Gateway-1、Gateway-2、Gateway-3。它们是同一份代码的三个进程，各自拥有独立内存。

```text
客户端 A → Gateway-1
客户端 B → Gateway-3
```

这就是以后跨 Gateway 投递问题的来源。

## 本地地址和公司地址

本地学习时，多个程序都可以在一台电脑上运行：

```text
Gateway  127.0.0.1:8090
Logic    127.0.0.1:9001
```

公司部署时，它们可以在不同机器或容器中。代码职责相同，只是地址、服务发现和共享依赖不同。

## 代码锚点

- `cmd/gateway/etc/gateway-api.yaml`：Gateway 端口和配置。
- `cmd/logic/etc/logic.yaml`：Logic 监听地址。
- `cmd/gateway/main.go`、`cmd/logic/main.go`：两个不同进程的入口。

只找 `package main` 和 `func main()`，暂不追函数调用。
